# 优化 PK 最终结果

**实验对象:** json-and-csv-data-transformation
**基线通过率:** 8/15 = 53.3%
**对比方式:** 从同一基线出发，两个分支各优化一轮，用同一套 15 个测试用例评估

---

## 结果一览

```
┌───────────────────┬──────────┬──────────┬───────────┐
│                   │ 基线     │ Darwin   │ Optimizer │
├───────────────────┼──────────┼──────────┼───────────┤
│ 通过率             │ 53.3%    │ 80.0%    │ 100.0%    │
│ 通过/失败          │ 8/15     │ 12/15    │ 15/15     │
│ 提升幅度            │ —        │ +26.7pp  │ +46.7pp   │
│ 代码bug修复         │ —        │ 0/4      │ 4/4       │
│ 结构改进            │ —        │ 是       │ 否        │
│ 改动行数            │ —        │ +68/-28  │ +19/-2    │
└───────────────────┴──────────┴──────────┴───────────┘
```

## Darwin 分支遗留的 3 个失败

| 测试 | 问题 | 为什么没修好 |
|------|------|-------------|
| 3,4 | csvjson 丢失数字类型 | Golden rule 说"保持数字类型"但没指名 csvjson 是罪魁祸首 |
| 7 | flattenJSON null 崩溃 | Golden rule 警告了 typeof null，但代码本身没改 |
| 10 | csvgrep 无法匹配 4.5 | 没加小数正则——darwin 优先修结构而非代码 |

## Optimizer 分支：4 个修复覆盖 7 个失败

| 修复 | 代码 | 解决的测试 |
|------|------|-----------|
| flattenJSON null 守卫 | `if (obj == null) return {};` 加在 `for...in` 前 | 7 |
| json_to_csv null 警告 | 标注 jq @csv 输出 "null" 字面量，引导用 Node.js | 1, 2, 15 |
| csv_to_json 类型保持 | `parseValue()` 自动检测 int/float/bool，标注 csvjson 的局限 | 3, 4 |
| csvgrep 小数正则 | `^([4]\.[5-9]|[5-9]\.\d)$` 匹配 ≥4.5 | 10 |

**12 行代码改动，消除全部 7 个二进制失败。**

## 核心结论

**代码级修复 > 结构级改进，在提升通过率上效果更显著。**

Darwin-skill 的 Golden rules 是有用的——它把通过率从 53% 提到了 80%。但它本质上是"告诉 agent 注意什么"，不是"把代码修好"。Agent 拿到更聪明的指令，但手里的工具还是坏的。

Skill-optimizer 的二进制 judge 直接定位到**哪个具体行为失败了**，迫使优化者把 bug 修掉。这是它的方法论优势：**二进制 judge 产出的不是"6/10"这种模糊评分，而是"jq 输出 null→null 字面量，违反了'should be empty string'标准"这种可以立即动手修的 bug 报告。**

最佳策略：**先用 optimizer 的二进制 judge 修代码 bug，再用 darwin 的结构优化提升整体质量。**
